You are a senior automation/backend engineer. Build a production-ready n8n workflow for an AI-text provenance and detection pipeline.

Do not merely explain the architecture. Implement it.

OBJECTIVE
=========
Build a system that accepts text and optional original-file metadata, checks reliable provenance first, checks applicable AI watermarks second, calculates statistical features third, uses free-tier AI models available through OmniRoute only where useful, combines the signals, and produces:

1. AI_GENERATED
2. HUMAN_LIKELY
3. REVIEW_REQUIRED
4. DETECTION_UNAVAILABLE

IMPORTANT SEMANTIC RULE
=======================
"HUMAN_LIKELY" must NEVER mean proven human.

It means:

"No sufficiently strong AI-generation signal was detected."

Do not claim certainty of human authorship from absence of an AI signal.

FREE-PROVIDER STRATEGY
======================
Use only free providers available to OmniRoute.

Preferred architecture:

1. Cerebras:
   - primary model-scoring provider
   - exploit token-level log probabilities where the selected model/API supports them
   - use for measurable model-derived statistics and/or secondary classification

2. NVIDIA NIM:
   - secondary classifier and fallback

3. OpenRouter free models:
   - additional fallback/ensemble source
   - use only models explicitly available as free

Do not assume a provider remains free forever.
Put provider names, model names, RPM, TPM, RPD and other limits into configuration variables rather than hard-coding them throughout the workflow.

Do not use paid credits or "free trial" balances as if they were free-tier capacity.

PROVENANCE
==========
Implement a provenance stage before text-only analysis whenever an original binary/file or metadata is available.

Recognize relevant provenance mechanisms such as:

- C2PA / Content Credentials
- signed manifests
- XMP
- EXIF where applicable
- generator metadata
- supplied provenance claims

Do NOT infer "AI-generated" merely from an unsigned metadata field.

The output schema must be:

{
  "found": true,
  "format": "C2PA",
  "signature_present": true,
  "signature_valid": true,
  "ai_claim": true,
  "issuer": "optional",
  "details": {}
}

Only treat provenance as strong evidence when the signature/claim is actually verified.

For a verified signed AI provenance result:

classification = AI_GENERATED
method = VERIFIED_PROVENANCE

Then stop the pipeline.

WATERMARK

Implement an HTTP interface like:

  "provider": null,
  "watermark_type": null,

The system must support model/configuration-specific watermark detectors.

Treat watermark detection as strong evidence only when the applicable detector is valid for the watermark family being tested.

Do not treat SynthID as a universal AI detector.

ENSEMBLE
========

Formula:

ensemble_probability =
    0.60 * statistical_probability
  + 0.25 * primary_model_probability
  + 0.15 * secondary_model_probability

Make these weights configurable.

Do not present them as scientifically universal weights.

DECISION THRESHOLDS
===================
Initial operational thresholds:

AI:
  probability >= 0.85
  AND confidence >= 0.70
  AND model disagreement <= 0.30

HUMAN_LIKELY:
  probability <= 0.20
  AND confidence >= 0.70
  AND model disagreement <= 0.30

Everything else:

REVIEW_REQUIRED

Make thresholds configurable.

Do not hard-code them in many workflow nodes.

CONFIDENCE
==========
Keep confidence conceptually separate from probability.

For the initial implementation, combine primary and secondary confidence:

confidence =
    0.5 * primary_confidence
  + 0.5 * secondary_confidence

Calculate model disagreement:

abs(primary_probability - secondary_probability)

Mark REVIEW_REQUIRED when confidence is low or disagreement is high.
