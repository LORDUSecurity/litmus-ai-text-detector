# Executive Summary

AI-generated text detection combines **provenance signals**, **watermark detection**, and **statistical/classifier-based analysis** to distinguish human from machine output. Modern approaches advocate a *multi-layered pipeline*: first check for *embedded provenance metadata* (e.g. C2PA content credentials), then *detect cryptographic watermarks* if any, and finally fall back to *statistical feature analysis* (log-probabilities, perplexity, n-gram patterns, entropy, etc.) with a trained or threshold-based classifier. High-confidence AI/watermark flags can be reported immediately, while ambiguous cases rely on feature-based scores or optional human review. 

Major AI providers have pledged AI-content transparency. For example, **OpenAI** uses C2PA-based *Content Credentials* for images/audio and offers a public verification API/portal. **Anthropic** will **embed invisible watermarks in all new Claude text** (EU-compliance) and attach signed provenance to generated files. These signals, if present, allow *proof* of origin rather than probabilistic classification. In their absence, detection relies on statistical “fingerprints”: AI text tends to maximize model log-likelihood (low perplexity) and reside at high-probability curvature regions, and often uses less diverse or highly predictable n-grams. 

We catalog concrete tools/APIs for each pipeline step. Paid cloud LLM APIs (OpenAI GPT-5.x/GPT-4.1, Anthropic Claude, Google PaLM, etc.) offer **log-prob access** and large context windows; many have pledged (or will add) watermarking. Open-source/free routes (Hugging Face models, OmniRoute gateway, etc.) provide large-model proxies or inference. We note each model’s token limits, rates, pricing, SDK support, and OmniRoute availability. We also suggest implementation snippets (e.g. using an LLM’s `logprobs` output) and classification logic (score thresholds, ensemble methods). Detection metrics (ROC/AUC, precision/recall, cost of false positives, calibration) and adversarial considerations (synonym/paraphrase attacks, threshold selection) are discussed. A summary table compares *paid vs free* options, and a Mermaid flowchart illustrates the full pipeline.

# 1. Detection Pipeline Overview

The recommended detection pipeline (reproducing the user’s flowchart) proceeds as follows:

1. **Provenance/Metadata Check:** Inspect the input text/file for any embedded provenance metadata or signatures. This includes C2PA Content Credentials (if present in e.g. a file) or provider-specific flags.
   - *If valid metadata is found and verifies correctly*, **label** the content accordingly (e.g. “AI-generated by [Provider]”).
2. **Watermark Detection:** If no definitive metadata, apply watermark detectors. This could involve provider-specific APIs (private preview) or algorithms that detect known watermark patterns (e.g. “green/red list” biases).
   - *If a watermark is detected*, flag the text as AI-generated, attributing the known source (e.g. “AI (Claude)”).
3. **Statistical Feature Extraction:** If no watermark signal, compute features from the text:
   - *Log-probabilities:* Query one or more large language models to get token log-likelihoods (e.g. via GPT-3.5/GPT-4, Claude, or local models).
   - *Perplexity:* Aggregate log-probs into a perplexity score.
   - *Entropy / Token Predictability:* Compute average token entropy or top-k rank statistics (GLTR-style).
   - *n-gram Overlap/Repetition:* Measure the presence of rare n-grams or degree of repetition (AI text often uses more common phrasing).
   - *Burstiness:* Compute variance of perplexity across segments; human text often has spikes (bursts) of surprise.
4. **Classifier / Threshold:** Feed these features into a detection model or threshold logic:
   - A **zero-shot detector** like DetectGPT uses log-prob curvature (perturb input slightly and compare log-likelihoods).
   - A **trained classifier** (e.g. logistic regression, SVM, random forest, or a small neural net) can combine features. Thresholds are set to balance false positives/negatives (e.g. optimize ROC AUC). High-confidence outputs (above threshold) are flagged as AI.
5. **Reporting:** 
   - If AI-detected, report “AI-generated” with a probability/confidence score.
   - If not, report “Human-likely”. Optionally, cases near the decision boundary can be flagged for **manual review**.
6. **Human Review:** Flag edge cases (ambiguous scores or policy-sensitive domains) for a human to inspect before final action.

# 2. Provenance & Metadata Verification

**Background:** Provenance metadata uses cryptographic signatures to attest origin. The Coalition for Content Provenance and Authenticity (C2PA) is a key standard. OpenAI and others have begun embedding C2PA-compliant *Content Credentials* into media. For images/audio, OpenAI attaches signed metadata (e.g. “generated by DALL·E 3”). A “Content Provenance API” lets tools check for these signals. For text, the industry is still evolving. 

- **OpenAI Content Credentials API:** OpenAI provides a verification portal (openai.com/verify) and API to detect content credentials in supported files. Although initially for images/audio, it establishes a model: when text-in-file has content credentials (C2PA metadata with signed origin data), we can parse it. Developer resources: OpenAI’s blog explains C2PA usage.
- **Anthropic Signed Metadata:** Anthropic commits that Claude will add *signed provenance metadata* when generating files (e.g. images, documents). If a received file (text doc, PDF, etc.) has this signature, it can be verified with Anthropic’s tools. 
- **Other Standards & Tools:** The open-source **Adobe C2PA SDK** and related libraries can extract/validate C2PA metadata from images or supported files.  For text-only content (e.g. plain text or HTML), there is no widely adopted metadata container yet. However, text shipped as a file (Markdown, PDF) could embed C2PA sections. Future tools may emit a token (e.g. “//OpenAI-Verified v1.0; signer=…”) as hidden text.

**Models/Services:** 

- *OpenAI Content Provenance API* (paid): Detects OpenAI’s C2PA credentials in a file. Requires an OpenAI API key. Supports images/audio currently. [Docs](https://openai.com/index/advancing-content-provenance/) explain usage. 
- *Anthropic (Claude) Metadata Check* (planned): When available, Claude’s APIs (or private verification API) will expose whether an output file carries Anthropic’s signature.
- *Hugging Face* and others: No native provenance API. However, one could use HF Inference for models that generate a static format and then apply C2PA libs.
- *C2PA Libraries (free):* Adobe’s [c2pa sdk](https://github.com/contentauth/c2pa) or [CAI](https://github.com/contentauth/content-credentials) can parse metadata. 
- *Data catalogs:* Some content management systems (e.g. Wordpress plug-ins) may strip or expose metadata. Custom scripts (exiftool, python libraries) could check for known markers.

**Implementation:** 

- **Verify Signature:** If input is a media/file, run a C2PA validation (e.g. `c2pa verify content.json`). If valid and signer known, *trust* the signatory. E.g. in pseudocode:
  ```python
  metadata = parse_c2pa(input_file)
  if metadata and verify_signature(metadata):
      report_origin(metadata)
  ```
- **Edge Cases:** If metadata is found but fails signature, treat as “inconclusive” (fall back to watermark).
- **Thresholds:** A valid signature is a binary condition. No numeric threshold needed. 

# 3. Watermark Detection

**Technique:** Watermarking injects a hidden pattern into AI-generated text. Commonly discussed is the **“green-list vs red-list” scheme** (Kirchenbauer et al. 2023) where the model secretly favors certain tokens. For example, Claude’s watermarks (once active) or future Google/Meta watermarks will use such a method. Detection involves checking if token choices are statistically biased.

- **Expected Signals:** If text was watermarked, some detector (often the provider’s private API) will identify the pattern. For instance, Anthropic’s upcoming *Watermark Detector API* (private preview for regulators) will take text and return “watermark present” or not.
- **Active Detection:** In absence of official API, one could attempt DIY detection if the scheme is known: e.g. count how often “green-list” tokens appear vs expectation. But without secret keys, false positives/negatives are likely. 
- **Known Work:** Research watermark methods (Kirchenbauer’s GPTWatermark and Zhao’s variant) suggest detection is *provably possible* if the key/list is known, but extremely hard for an outsider to reverse-engineer.
- **Provider Tools:** 
  - *Anthropic Watermark Detector:* Anthropic plans an enterprise API for EU compliance (as of late 2026, by-request). No public docs yet. 
  - *OpenAI:* There is no announced text watermark. OpenAI focuses on metadata/C2PA instead.
  - *Google:* Likely to comply via internal methods (no public info yet).
  - *Others:* Mistral, Meta (LLaMA) have no announced watermarks. 
- **Free/3rd-party:** No general free text-watermark detectors exist, since watermark algorithms are proprietary. For images/audio, tools like Google’s `vision.watermark` API exist, but not for text.

**Implementation Plan:** 
- **API Call:** If available, call Anthropic’s watermark detector: 
  ```python
  result = claude_watermark_detector(text)
  if result.watermarked:
      report_AI_with_source("Claude")
  ```
- **Fallback:** If no API, proceed to feature analysis. 

# 4. Statistical Features and Classifiers

When no watermark is found, we use **statistical cues**. These include:

- **Log-Probabilities / Perplexity:** Human text tends to be *less probable* under a generative model than the model’s own output. We query one or more LLMs for the text’s log-prob. e.g. using OpenAI:
  ```python
  resp = openai.ChatCompletion.create(model="gpt-5.6-luna", 
      messages=[{"role":"user","content":input_text}], 
      logprobs=0, echo=True)
  logp_sum = sum(token.logprob for token in resp.choices[0].logprobs.tokens)
  perplexity = exp(-logp_sum / N_tokens)
  ```
  Providers:
  - **OpenAI GPT-5.x/GPT-4.1:** Chat/completion endpoint with `logprobs`. Huge context (128k+). Paid: ~$0.20–$10 per 1M tokens. Rate ~50–100 req/min, 350k tokens/min (Tier 5). SDK: `openai` Python. OmniRoute: Yes (models like `gpt-5.6-luna` are accessible through a OpenAI key; free via OmniRoute combos if fallback).
  - **Anthropic Claude (Opus/Sonnet/Fable):** Claude API can return `log_probs` with `logprobs=True`. Context up to 1M tokens. Pricing $1–$10 per 1M input, $5–$50 output. Rate limits ~20–30 requests/min by default (info not public, but enterprise supports higher).
  - **Google PaLM2 / Vertex AI:** PaLM2 is accessible via Vertex (Gemini is Google’s). They allow logprob scores via a `logprob` parameter. Pricing (Vertex) ~$3–$20 per 1M tokens for PaLM 2 L/XL. Rate ~ 60–100 qpm.
  - **Open-Source LLMs (free):** Hugging Face GPT2/GPT-NeoX/LLaMA models. E.g. `transformers` can compute token log-probs locally (no cost). Context limits vary (512–2048 typically, or more with custom long-context models). These require GPU for speed. OmniRoute: Many HF-based models are accessible via free pipelines or hosted GPUs (e.g. HF Inference ~10K tokens/day free, or hosting own HuggingFace Inference endpoints).
  
- **Token-Level Signals (Entropy, Top-K):** Compute per-token entropy or the rank of each token in the model’s top-k distribution (GLTR idea). For instance, run each token through the model with `logprobs` and note where the actual token ranks among predicted tokens. Human text has more low-frequency words (lower rank scores). Libraries: Use the same LLM calls as above. 
- **N-gram Overlap & Repetition:** Measure how much of the text is *cannibalized* from training data via n-gram overlap. (E.g. the *DetectGPT* paper noted overlap between source model output and real data can trick detectors, called “contamination”). In practice, one can compare the text’s n-grams against large corpora or use plagiarism tools. 
- **Burstiness:** Compute variance of logprob or perplexity along the text. Human writing often has bursts of surprising tokens, unlike uniformly “smooth” AI text. For example, split text into windows and compute perplexity per window, then measure variance. 
- **Calibration of Log-Probs:** LLMs can be overconfident. One can calibrate scores by e.g. dividing log-probs by a temperature or normalizing relative to a control (self-cross-entropy). (No simple off-the-shelf, but e.g. compare logp under one model vs another).
  
**Classification:** Combine features via:
  - **Thresholding:** Use a rule such as “if perplexity < X” or “average logprob > Y” then flag. (OpenAI’s early advice: “if the average log probability is high (i.e. low perplexity) compared to human baseline, suspect AI.”)
  - **Zero-shot Detector (DetectGPT):** As per Mitchell et al. (2023), perturb the text with a generic model (e.g. T5 rewrites), compute logp for original vs perturbed under a target LLM. If the original is significantly *more* probable than its perturbations (negative logprob curvature), label as AI.
  - **Supervised Classifier:** Train a binary classifier on features (e.g. logistic regression on [mean_logp, var_entropy, ngram_score, top1_ratio, …]). Use datasets of human vs AI text (like Giant Language Model Testbed). The classifier outputs a probability or score.
  
**Thresholds and Metrics:** 
- Typical evaluation uses **ROC AUC**, precision/recall, etc. DetectGPT achieved ~**0.95 ROC AUC** on benchmark tasks. We would select a threshold to balance false positives (human flagged as AI) vs false negatives. In high-stakes settings, one might set threshold so false positive rate (FPR) is extremely low (e.g. 0.5%) to avoid accusing humans erroneously, at cost of some misses.
- Calibration (Brier score) can assess confidence. A well-calibrated detector’s probability scores should match observed frequencies.
- **Cost of Errors:** AI false negatives (missed AI) can be mitigated by flagging uncategorized text as “likely human” but possibly reviewing. AI false positives (misclassifying human as AI) are more serious ethically. Thresholds should reflect domain: e.g. in academia, lean conservative to reduce false accusations.

# 5. Adversarial and Robustness Considerations

Detection methods can be **brittle** to adversarial edits. For example:
- **Paraphrasing:** Changing wording or structure (via synonym replacement or re-generation) can defeat watermarks and confuse statistical detectors (alter probability patterns).
- **Snippet Injections:** Inserting a span of “human-like” text into an AI output raises perplexity locally, possibly evading burstiness/perplexity checks.
- **Training-overlap Attacks:** If AI output closely mimics real data (training overlap), n-gram detectors fail. Conversely, rare phrases (as in legal documents) might falsely trigger AI suspicion.
- **White-box Attacks:** As shown by Sadasivan et al., if detection relies on model internals, an attacker could adjust generation to hide those cues, making detection impossible without watermark.
  
**Mitigations:** 
- Use **multiple signals** (metadata + watermark + stats) for defense-in-depth.
- For classifiers, augment training with paraphrased/attacked examples, or use models robust to style changes.
- Monitor **detector calibration drift**: newer AI models may require retraining detectors.
- When watermarks are available, they are provably robust absent tampering (but fail if text is heavily edited).
- In policy: any automated classification should allow human appeal/review.

# 7. Implementation Notes & Code Snippets

- **Fetching Log-Probs (OpenAI):**
  ```python

  openai.api_key = "sk-..."

      model="gpt-5.6-luna", 
      messages=[{"role": "user", "content": text}], 
      logprobs=0, echo=True
  )
  log_probs = resp.choices[0].logprobs.token_logprobs  # list of logp for each token
  ```

# 8. Evaluation and Metrics

Detection performance should be measured by **ROC AUC**, **precision/recall**, and **confusion matrices** on labeled test sets.  Standards:
- **ROC/AUC:** Summarizes TPR vs FPR trade-off. DetectGPT reported ~0.95 AUC, a strong result. 
- **Precision/Recall:** Especially important if class imbalance (often fewer AI than human texts).
- **Calibration:** Brier score or reliability diagram: are predicted “AI probabilities” accurate? 
- **Error Costs:** Domain-specific. In education, FPs (labeling a student’s writing as AI) are ethically severe. Might set threshold for near-zero FPR at cost of some FNs.
- **Adversarial Robustness:** Evaluate on adversarially perturbed AI text (paraphrased by other LLMs) to estimate vulnerability. 

# 9. Adversarial Concerns

No detector is foolproof. Known issues:
- *Watermarks:* Can be destroyed by re-encoding/ paraphrasing. A robust watermark (like GPTWatermark) is provably detectable if not edited, but any edit breaks detection.
- *Statistical:* As Sadasivan et al. argue, if a classifier knows the model’s distribution, an attacker can sample text that “looks” human, forcing the detector to err.
- *Bias:* Detectors often misclassify non-native-English text or domain-specific jargon as AI. Validate on diverse corpora.
- *Countermeasures:* Use ensemble of cues; in critical apps, flag ambiguous cases for humans.
